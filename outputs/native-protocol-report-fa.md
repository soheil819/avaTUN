# گزارش آزمون زندهٔ پروتکل‌های تونل

**تاریخ:** ۱۱ نوامبر ۲۰۲۶  
**میزبان‌ها:** سرور مرکزی `65.109.179.222` و `fsn1` با آدرس `91.107.139.87`

برای هر لینک آزمایشی، پروفایل جداگانه روی هر دو سرور ساخته شد، وضعیت سرویس و رابط بررسی شد و از هر سمت به IP داخلی سمت مقابل ping زده شد. برای ERSPAN که یک‌طرفه است، رابط آزمایشی روی فرستنده ترافیک تولید کرد و شمارندهٔ RX سمت گیرنده بررسی شد. پس از ثبت نتیجه، تمام پروفایل‌ها و رابط‌های موقت پاک شدند.

## ایرادهایی که اصلاح شدند

- **GRE-FoU:** ابتدا GRE بی‌کلید با رابط GRE آزمایشیِ از قبل فعال روی همان جفت IP بیرونی برخورد کرد (`RTNETLINK: File exists`). به‌روزرسانی FoU از GRE key پشتیبانی نمی‌کرد. پشتیبانی key به driver، اعتبارسنجی و فرم پنل اضافه شد؛ GRE-FoU با key یکتا دوباره ساخته شد و ping دوطرفه گرفت.
- **پاک‌سازی FoU:** اگر ساخت رابط پس از ثبت FoU شکست بخورد، حالا پورت FoU و رابط ناقص پاک می‌شوند؛ توقف پروفایل هم در صورت نبودن رابط خطا نمی‌دهد.
- **پاک‌سازی IPsec:** helper پنل اکنون اجازهٔ حذف فایل‌های موقت swanctl را دارد؛ فایل‌های دو آزمون IKEv2/NAT-T پس از آزمون حذف شدند.

## وضعیت بعد از آزمون

- تونل‌های اصلی GRE و VXLAN روی هر دو سرور فعال ماندند و پایش پنل برای هر چهار سمت `up` گزارش کرد.
- در `/etc/tunnelmgr/network` فقط پروفایل‌های اصلی `native-demo-gre` و `native-demo-vxlan` باقی مانده‌اند. رابط آزمایشی، ثبت FoU، نشست L2TPv3 و فایل‌های swanctl آزمایشی باقی نماند.
- تلاش جداگانه برای ساخت GRE دوم بدون key عمداً به‌دلیل وجود GRE بی‌کلید اول روی همان outer pair رد شد. پنل برای جلوگیری از این برخورد هنگام خالی‌بودن فیلد GRE key، کلید یکتا می‌سازد.
