پورت‌فوروارد TCP با HAProxy
سرور ورودی را انتخاب کن؛ سپس مسیرهای تونلی همان سرور را به‌عنوان pool مقصد بگذار. HAProxy سلامت پورت مقصد را بررسی می‌کند و مسیرهای خراب را از چرخش خارج می‌کند.
در حال بررسی HAProxy…
این نسخه TCP را مدیریت می‌کند. پورت شنود فقط هنگام ذخیرهٔ قانون باز می‌شود. برای مقصد، برنامه باید روی IP داخلی peer، IP خصوصی‌ای که از مسیر BGP/OSPF اعلام شده، یا مقصدی که مسیرش از رابط TUN/IPX عبور می‌کند گوش کند؛ مسیر IPX هنگام اعمال قانون بررسی می‌شود.
در Failover دقیقاً یک مسیر را «اصلی» و بقیه را «پشتیبان» کن. پشتیبان فقط وقتی مسیر اصلی ناسالم باشد استفاده می‌شود. اتصال‌های TCP قطع‌شده با تغییر مسیر خودکار از ابتدا وصل می‌شوند.

HTTPS پنل با گواهی Let’s Encrypt
یک پورت واحد برای HTTP و HTTPS انتخاب کن. پورت ۴۴۳ برای سرویس‌ها آزاد می‌ماند.
در حال خواندن وضعیت…
دامنه باید به IP همین سرور اشاره کند. برای صدور و تمدید خودکار گواهی، TCP پورت ۸۰ باید از اینترنت به سرور برسد و سرویس دیگری آن را اشغال نکرده باشد؛ رکوردهای A/AAAA دامنه هم باید به همین سرور برسند. ورود HTTP فعلی حفظ می‌شود؛ HTTPS روی همان پورتی باز می‌شود که اینجا انتخاب می‌کنی.
صدور گواهی در پس‌زمینه انجام می‌شود. پنل پس از نصب گواهی، اتصال‌های HTTP و HTTPS را روی همین پورت می‌پذیرد. اگر پورت را تغییر دهی، نشانی پنل هم به پورت جدید منتقل می‌شود.

ساخت تونل
نوع، جهت اتصال و مشخصات دو سر تونل را وارد کنید.
پنل IP مبدأ مورد انتظار هر سمت را از IP طرف مقابل می‌سازد. این تنظیم فقط مبدأ بسته‌های خام IPX را تغییر می‌دهد؛ IP واقعی دو سرور ثابت می‌ماند.
برای TUN/TCP آدرس‌های داخلی دو peer را وارد کن.
پنل پس از بررسی هر دو سرور، شناسه‌های tunnel و session را تصادفی می‌سازد و برای Encap=UDP در هر سرور پورت آزاد انتخاب می‌کند؛ بیرون بازهٔ ephemeral را ترجیح می‌دهد و اگر سیستم کل بازه را موقت بداند، یک پورت اشغال‌نشده را برمی‌گزیند؛ بعد از ساخت، پورت‌ها را در فایروال دو سر باز کن.
پنل IP داخلی بدون تداخل، شناسهٔ یکتای IKE برای همین تونل، PSK قوی مشترک و نقش آغازگر/پاسخ‌دهنده را خودکار تنظیم می‌کند.
تنظیمات سمت B خودکار از سمت A ساخته می‌شود؛ IPها، شناسه‌ها و پورت‌های جفتی معکوس می‌شوند.
